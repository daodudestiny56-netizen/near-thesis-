# NEAR Agent Census

**Is NEAR becoming the chain that software lives on? This repo measures it.**

A re-runnable census that classifies NEAR activity as *human-like* or *automated* from on-chain
behaviour alone, then reports the **automated share of transactions and fees over time, who pays the fees,
and whether software activity is growing in **absolute** terms, each with a confidence interval and a stated accuracy.**

Built for the [NEAR HACKATHON](https://nearhackathon.com) · track: **Investment Thesis** (`thesis`).

**Headline results** (computed from 2,370 random blocks and 6,240 transactions, 2022-01 to 2026-11; regenerated by `python -m census reproduce`, full tables in [RESULTS.md](RESULTS.md)):

* **Level.** Over 2026-06 to 2026-11, **61.1%** of sampled transactions were initiated by accounts that behave like software (95% CI 57.0% to 65.1%; 57.1% to 62.7% across classifier cut-offs).
* **Trend.** 2024-01-2024-06 to 2026-06-2026-11: 23.1% to 61.1% (+38.0 pts, 95% CI +32.3 to +43.7).
  Without the lifetime-volume rules (which grow with account age) it is 15.2% to 32.7% (+17.5 pts, CI +11.6 to +23.7): the direction survives, the size shrinks.
* **Fees.** Automated accounts initiated 73.7% of fees (CI 62.9% to 81.2%) and fee payers classified as automated paid 82.5% (CI 72.5% to 90.3%); 42.4% of transactions were relayed.
* **Accuracy (held-out test split, n=141).** Recall for automated 85.0% (Wilson CI 64.0% to 94.8%), for human 99.2%, balanced accuracy 92.1%, ROC AUC 0.99. Labels are biased toward self-declared bots, so treat this as an optimistic ceiling.
* **Absolute activity (per second, block-time corrected).** Total activity went 64.4 to 8.0 tx/s; automated went 14.9 to 4.9 tx/s (x0.33, 95% CI x0.26 to x0.42); fee burn initiated by automated accounts went 0.0102 to 0.0059 NEAR/s. **The share rose because other activity fell faster, not because software activity grew.**
* **Thesis verdicts** (decided by code from the intervals, see [THESIS.md](THESIS.md)): 1 inconclusive, 3 descriptive, 2 not supported, 7 supported.

## The problem

NEAR's pitch for the next few years is that AI agents will transact on it: through NEAR Intents, function-call
keys, meta-transactions and cheap fees. An investment thesis built on that needs a number: *how much of NEAR's
activity is already software, and is it rising?* Nobody publishes one, and "agent" claims are usually
asserted, not measured. This project measures it, with error bars, and says plainly what it cannot know.

## Try it (about two minutes, offline)

Requires Python 3.10+. No account, no API key, no network for these steps.

```bash
git clone https://github.com/daodudestiny56-netizen/near-thesis-.git
cd near-thesis-
pip install -r requirements.txt

python -m unittest discover -s tests -v     # offline unit tests -> "OK"
python -m census reproduce                  # classify -> validate -> analyze -> report -> dashboard
python -m http.server 8000 --directory docs # then open http://localhost:8000
```

* After `reproduce`, **`RESULTS.md`** and **`docs/index.html`** are rebuilt from the committed sample in
  [`data/derived/`](data/derived/). The last line printed is the latest month's automated share with its interval.
* On the page, open **"How this is computed"** under any chart for the exact function behind it, and
  **"Table view"** for the raw numbers.
* To re-draw the sample from the live chain instead of using the committed one (several hours anonymously; minutes
  with a free [FastNEAR key](https://dashboard.fastnear.com) in `.env`, see `.env.example`):

```bash
python -m census collect && python -m census reproduce
```

## What it measures

For each calendar month the census draws **45 blocks uniformly at random** (seeded), takes every transaction in them, and for each:

1. finds the **initiator** (the real signer, resolving relayed meta-transactions) and the **fee payer** (who signed on chain);
2. profiles each account from its **last 200 signed transactions**: gap regularity, machine-speed bursts,
   whether it ever rests, volume, failure rate, and whether its calls look like function-call-key calls;
3. scores it with a transparent, additive rule list (`census/classify.py`): **automated**, **human**, or
   **low-activity** (too little history to judge, never silently called human);
4. estimates **shares of transactions and of fees** with a cluster bootstrap over blocks for the interval.

Reported: monthly automated share (with upper bound), fees *initiated* vs *paid* by automated accounts,
relayed share, share addressed to `intents.near`, concentration of automated activity, a trend
absolute activity per second (so a rising share is not mistaken for rising activity), and a leave-one-rule-out ablation.

## How NEAR fits in

NEAR makes this measurable, and the metrics are NEAR-specific:

* **Per-account transaction history is public and queryable**, so behaviour (timing, rest, volume) can be read straight off the chain.
* **Meta-transactions (NEP-366)** split *who acts* from *who pays*. On most chains they are the same account; on NEAR they often are not, which is why the census reports both.
* **Function-call access keys** are NEAR's native way to give software restricted authority, so call shape is a signal.
* **NEAR Intents** is where cross-chain agent activity is expected to concentrate; the census tracks `intents.near` traffic.

## How accurate is it?

Validated against labels built from evidence the classifier never sees (NEAR Social profiles for humans,
self-declared infrastructure roles for bots), on a **held-out test split fixed by a hash of the account id**.
The results table, with Wilson intervals, ROC AUC, a threshold sweep and the ablation, is in
[RESULTS.md](RESULTS.md). The **limits are stated up front** in [METHODOLOGY.md](METHODOLOGY.md#known-limits-of-the-validation-please-read):
the labels are biased toward self-declared bots and engaged humans, so accuracy is an **optimistic ceiling**, and
"automated" is a behavioural class that **includes AI agents but cannot isolate them**.

## Repository layout

```
census/                 the pipeline (stdlib + numpy + pandas)
  client.py             throttled, cached FastNEAR API client
  heights.py            date -> block height
  collect.py            stage 1: sample blocks, profile accounts
  features.py           behavioural features (no names, no off-chain data)
  classify.py           stage 2: explainable rule-list classifier
  labels.py             builds validation labels from independent evidence
  validate.py           stage 3: held-out accuracy, ablation, bias adjustment
  analyze.py            stage 4: shares, absolute levels, bootstrap intervals
  report.py             writes RESULTS.md
  dashboard.py          stage 5: writes docs/index.html (self-contained, offline)
data/derived/           the committed sample and computed results
data/labels/            labelled accounts, evidence, and review notes
docs/index.html         the dashboard (also deployable on GitHub Pages)
tests/                  offline unit tests with synthetic accounts of known behaviour
tools/make_video.py     records the demo video from the dashboard (presentation helper)
```

## Hackathon disclosures

* **Built during the hackathon window.** The repository was created for this event; no code predates 1 Nov 2026.
* **Libraries:** `numpy`, `pandas` (analysis); everything else is the Python standard library. The dashboard is
  plain HTML/SVG/JavaScript with no dependencies and no network calls at view time. `tools/` additionally uses
  `playwright`, `imageio-ffmpeg` and `edge-tts` (Microsoft's online speech service, which receives the narration text) to record the
  narrated demo video; none of them is needed to run the project.
* **Data source:** the public [FastNEAR Transactions API](https://docs.fastnear.com/tx) and NEAR Social (`social.near`) via public RPC.
* **AI assistance:** the code and documents were written with Claude Code (Anthropic). Validation label candidates were
  harvested by script and reviewed with Claude Code's help; the review log, including every removal and why, is in
  [`data/labels/review_notes.md`](data/labels/review_notes.md) and is open to audit. Submission decisions are the author's.
* **No wallet, no keys, no transactions:** the project only reads public chain data. There is nothing to deploy to mainnet.
